This paper introduces PULSAR, a 3.3 MB monolithic standalone native x86-64 execution engine implemented in pure C with custom handwritten AVX2/F16C vector micro-kernels. PULSAR operates with Zero-Python, Zero-CUDA, and Zero-External Runtime Dependencies, memory-mapping a 4.3 GB Google Gemma-2-2B model directly into physical address space. Crucially, PULSAR implements an 18-Layer Latent Flight Telemetry Pipeline, projecting residual states at every layer onto a calibrated 4D cognitive coordinate space: Truth (T), Safety (S), Certainty (C), and Domain Anchor (D). 1. Introduction: The Silicon Imperative / 引言與矽晶片命題

Modern deep learning deployment frameworks have progressively isolated practitioners from the underlying silicon. A conventional baseline inference pipeline for a 2-billion parameter model mandates a massive software pyramid: a Python interpreter runtime (~100 MB), PyTorch dynamic shared objects (~2 GB to 4 GB), NVIDIA CUDA driver libraries (~5 GB to 8 GB), and auxiliary Python package DAGs. This layered abstraction induces non-deterministic thread contention, unpredictable operating system page-fault spikes, multi-second cold-start delays, and significant vulnerability attack surfaces. In regulated financial engines and industrial edge systems, such fragility is unacceptable.

Concurrently, contemporary LLMs are treated as opaque, end-to-end black boxes: text goes in, autoregressive sampling loops run, and token streams emerge. When an epistemic failure (hallucination) occurs—such as declaring Taiwan's statutory VAT rate to be 15% rather than the legally codified 5%—practitioners can only observe the finalized output text. The internal causal chain of how, where, and at which layer the representation diverged from ground truth remains entirely invisible.

PULSAR addresses both challenges simultaneously by executing full-precision FP16 forward inference inside a 3.3 MB monolithic Windows PE64 executable, while providing non-invasive, layer-by-layer 4D cognitive telemetry directly on hardware execution registers.

2. Monolithic Silicon Architecture / 單體矽晶片架構

PULSAR bypasses the entire dynamic Python runtime through direct virtual memory management. The 4.3 GB Google Gemma-2-2B binary weight file is memory-mapped via Win32 CreateFileMappingA and MapViewOfFile into physical address space with zero-copy overhead.

  • Model Parameters: Hidden dimension $d_{ ext{model}} = 2048$, feed-forward dimension $d_{ ext{ff}} = 16384$, query heads $n_{ ext{heads}} = 8$, key/value heads $n_{ ext{kv}} = 1$ (Multi-Query Attention), total layers $L = 18$.
  • AVX2/F16C Vector Core: General Matrix-Vector (GEMV) multiplications and Gated Linear Units (GeGLU) are executed using custom handwritten SIMD loops unrolled across eight 256-bit YMM registers. Hardware instruction _mm256_cvtph_ps uncompresses 16-bit floats to 32-bit registers on-the-fly, while _mm256_fmadd_ps executes fused multiply-accumulates across 8 parallel lanes.
  • SMP Micro-Kernel Thread Pool: A dedicated 4-core micro-kernel synchronizes work batches through atomic spinlocks without operating system thread scheduler context-switch penalties.

5. Deterministic Verification & State Hash / 確定性防偽驗證

To verify that telemetry data represents genuine physical computation rather than synthesized simulation, PULSAR calculates a 32-bit Fowler–Noll–Vo (FNV-1a) checksum over the raw 8,192-byte activation array $\mathbf{x}^{(L)}$ at each layer boundary: 

static uint32_t compute_hash_32(const void* data, size_t bytes) {
    const uint8_t* p = (const uint8_t*)data;
    uint32_t h = 2166136261u; // FNV offset basis (0x811C9DC5)
    for (size_t i = 0; i < bytes; i++) {
        h = (h ^ p[i]) * 16777619u; // FNV prime (0x01000193)
    }
    return h;
}

Scientific Properties: (1) Avalanche Sensitivity: Any 1-bit drift in the 2,048 floating-point values completely randomizes the 32-bit integer; (2) Deterministic Reproducibility: Re-running the prompt on any compliant x86-64 machine produces bit-for-bit identical hashes (e.g., [0xCF00ACCF]); (3) Zero Weight Leakage: Compressing 8,192 bytes into 4 bytes yields a 99.95% mathematical information loss, rendering weight reconstruction mathematically impossible.

6. The Manufacturing Rule-BOM Paradigm / 製造業 Rule-BOM 神經換料拓撲

PULSAR treats neural networks through the lens of industrial Bills of Materials (BOM). Instead of performing costly end-to-end retraining when a model fails:

  • Standard Stations: Intermediate layers (Layers 08, 09, 10) function as standardized sampling and dynamic bus injection sockets.
  • Dynamic Substitute Materials (替代料): By isolating the causal failure to Layer 14/15, target subspace orthogonal projections can be hotswapped at runtime, replacing contaminated attention heads with deterministic business rules without modifying the remaining 99.9% of neural weights.
  • Sub-Millisecond Execution: Activation replacement executes in < 1 ms on CPU RAM, guaranteeing compliance in regulated enterprise environments.

7. Operational Boundaries & Ethical Notice / 運行邊界與倫理聲明
